MCP is quickly becoming the standard for connecting LLMs to real systems, and with that reach comes a whole new set of ways to get it wrong. This session walks through seven of them, mapped to the seven deadly sins: gluttony (resource abuse), sloth (lazy error handling), wrath (aggressive polling), greed (permission overreach), pride (overengineering), envy (tool sprawl), and lust (unsafe exposure). Using a scenario where an MCP server is handed to an overzealous LLM—triggering memory leaks, runaway polling, and dangerously broad permission scopes—we'll look at the patterns and symptoms behind each sin, and the practices that keep MCP deployments dependable. The goal: ship with absolution, instead of yet another pager alert.
